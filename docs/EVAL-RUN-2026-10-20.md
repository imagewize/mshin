# Model Evaluation Run — 2026-10-20

> *"The Wheel weaves as the Wheel wills, and the Pattern reveals itself only to those who look with clear eyes and record what they see."*

The first harness-driven model comparison against a Node whose tools really
execute, run as the input the Phase 2 hardware decision calls for. Two runs,
one report each, both reproduced verbatim below. The reasoning lives in
`docs/CYBERSECURITY-AGENT-ROADMAP.md` (Phase 2) and `CHANGELOG.md` (0.16.2);
this file is the raw record.

---

## Overview

- **Harness:** `clients/mshin-cli/eval-harness.js`, case set
  `clients/mshin-cli/eval-config.model-comparison.json`.
- **Node:** the `mshin-node` Lima VM, reached at `http://localhost:3000`
  (the host forward of the guest's MCP Node), 6 tools exposed. Verified
  before the run: `sudo -n whois example.com` and `sudo -n nmap -p 22,80
  127.0.0.1` return real output in the guest, so the suite exercises tool
  *output*, not the failure branch.
- **Ollama:** native on the 16GB M1 Pro authoring host
  (`http://localhost:11434`).
- **Models:** `mshin` (7B persona), `qwen3:8b`, `qwen3:4b` in the baseline
  run; `qwen3:32b` in a second, reduced run (2 cases) after the pull.

## Findings

| Model | Overall | Verdict |
|-------|---------|---------|
| `mshin` (7B persona) | 4/4 PASS | Chains, pivots, and reports honestly; 7.8–67.8 s per case |
| `qwen3:8b` | 4/4 PASS | Indistinguishable from the persona on this case set; 7.2–68.2 s per case |
| `qwen3:4b` | 3/4 | Below the bar: fabricated a bare `nikto -h http://127.0.0.1` command as its final answer instead of calling the tool; slower than 8B on every case |
| `qwen3:32b` | 0/2 | Unrunnable on this host: every case died at the 600 s per-turn timeout before a single tool call |

- **Context high-water mark:** 947 tokens on the hardest completed case —
  far under the compaction budget. There is no context pressure to buy
  hardware out of yet.
- **The 32B ceiling is measured, not assumed.** `qwen3:32b` (20 GB, 40k
  context) loads at 21 GB split 47%/53% CPU/GPU with system free memory at
  5% on the 16GB host. Both cases — including the one-sentence no-tool
  control — timed out at 600 s on the first turn with zero tool calls. The
  32B tier needs a ≥32GB machine before it can be evaluated.

## Reproducing

```
limactl start mshin-node
limactl shell mshin-node -- sudo systemctl restart mshin-node
cd clients/mshin-cli
node eval-harness.js -f md -o <output-dir> eval-config.model-comparison.json
```

The case set targets the Lima local-dev path (`nodeUrl
http://localhost:3000`); run it against a production Node by changing
`nodeUrl` to `http://192.168.1.100:3000` (plus `nodeToken` if the Node has
`MSHIN_NODE_TOKEN` set). Cleanup per
`docs/AGENT-LOOP-INVESTIGATIONS.md`: unload models with a `keep_alive: 0`
generate call and stop the VM when finished.
